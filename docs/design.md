# Paperlife 国内家庭口述史设计 v0.4

更新：2026-10-23。目标：国内长辈独立用四川话完成低延迟语音采访；亲属在授权范围校对、确认事实与文学草稿。用户授权尽量执行、将必须本人处理的事项打包；以下云选型为本轮建议，不代表已购买或已迁入国内。

## 决策与替代方案

| 方案 | 收益 | 代价 | 决策 |
|---|---|---|---|
| 腾讯云大陆部署 + 豆包语音 | 微信/短信/COS资料较集中；业务与模型供应商解耦 | 跨云语音链路需测延迟；两套账单 | 推荐生产默认，待主体和地区确认 |
| 火山大陆部署 + 豆包语音 | 已有语音服务，可减少平台数量 | 微信/短信仍需独立资质；同供应商也不保证地域路由最低延迟 | 合理备选，以实测为准 |
| 阿里云大陆部署 + 国内模型 | 通用计算/OSS生态完整，微信也可接 | 当前没有可直接复用的阿里资源与审核资产 | 有现成企业资源时优先 |
| GCP 香港 | 复用开发环境最快 | 国内手机到境外链路不确定；不适合作为既定国内生产数据落点 | 保留开发、灰度验证 |

微信小程序不要求使用腾讯云。决定生产云的是大陆可达性、主体/备案、运维与数据落点，不是微信品牌。首期单VM Docker+私有数据卷；正式多人持续使用前升级私有对象存储(COS/TOS/OSS)、加密备份和数据库。PostgreSQL与对象存储仍是迁移目标，本轮不能声称已实现这些后端。

## 已有资产与拆分

FastAPI + 浏览器 AudioWorklet + 豆包 O2.0 WebSocket。保留原声、原始turn、校对版本、source、items、processing_jobs和capability链接。公开仓库只包含通用代码/文档/虚构测试，不导入旧Git历史、用户数据库、真实姓名、链接token或录音。独立auth数据库采用相同密码摘要格式以便离线迁移，但不迁入交易表；身份以内部user_id为授权主体，微信openid/手机号只是登录凭据，不是家人授权。

迁移需停旧站写入→SQLite backup快照→复制音频并校验sha256→导入所需成员账户→验收角色/原文/链接→切换域名→旧链接按保留fragment方式重定向→观察→保留可回滚快照。迁移前不让两套应用写同一档案。旧站保持服务；本轮新仓库可独立运行，生产切换需目标云/域名等输入。

## 实时采访与纠错

主流程只走端到端语音：采集→语音模型→音频播放。优先保持稳定的O2.0协议，显式tts.extra.explicit_dialect=sichuan；可配置mandarin回退。新全双工API作为后续对照，不把不同协议字段混用。配置成功与四川本地老人听感是两项验收。

模型应在听懂意义前不装作听懂：人名/地名/年份关键且不确定时问一次中性澄清，例如“您说的这个名字，是哪几个字呢？”不能先列出猜测的汉字让老人选择；不清楚也接受，记为待核实。奇怪的句子不一定是ASR错误，可能是方言、旧称或记忆差异；不按现代常识静默纠正。长停顿给空间，不能通过把VAD设得极短换取漂亮延迟。

轻量检查器仅处理final文本，标记明确的“听不清/不确定”、异常时间、说话人主动纠正等信号，去重并保存原句/秒数。它没有声学置信度，不把启发式风险当“识别置信度”。本轮即时追问由端到端模型的采访策略承担，检查器只做旁路记录；不声称每个疑点都已自动追问。后续可用独立ASR二遍或全双工工具调用加入更强校验，必须先验证更新上下文和打断时序，避免双重追问。常见人名热词仅来源于家人确认的当前档案，不跨人串资料。

## 采访策略（非心理治疗）

依据口述史与创伤知情原则：清楚告知AI和录音；先建立安全感与选择权；一次一问、开放式提问、具体细节、耐心沉默；不诱导、不替人补记忆、不反复逼问时间或姓名。敏感话题先问愿不愿意谈；表达疲惫/拒绝时换话题或结束。不能诊断、承诺疗愈或模仿亲人身份。先让故事讲完，再核对细节；结尾让讲述者补充或更正。策略文件可版本化，并用虚构对话情景做行为评估。

## 延迟与评测

记录：ASREnded→首个返回音频（服务器）、连接建立耗时、断连原因；不记录原文到日志。服务器指标不含麦克风判停时间与手机播放缓冲，不能当作用户感知延迟。下一阶段目标待真机验收：常见回合结束到开口p50≤2s、p95≤4s。现有保守的2.5秒判停等待可能已超过该目标，因此不能声称当前达标；需比较语义判停/全双工后再调整。无抢话、弱网可恢复优先于单一数字。至少Android微信/iPhone微信/系统浏览器、家庭WiFi/移动网络各测；同时记录人名/地名准确度、每10分钟校对耗时、追问是否中性、隐私边界与拒答恢复。未达到目标时按分段耗时定位，不承诺仅搬云就解决。

## 登录与小程序

保留长辈免密码采访链接，家人可撤销。微信登录由后端拿一次性code换openid；客户端自报openid不可信。微信取手机号是单独能力/授权，不等于wx.login。手机号OTP需供应商资质/签名/模板；5分钟过期、单次消费、尝试次数和发送频率限制、仅服务端保存摘要、不向前端回显。首次登录只创建普通账户，不自动获得家族档案；绑定两种登录必须分别验证，不凭相同昵称合并。

本轮做可运行的服务端适配与关闭状态，小程序录音前端、平台审核和真实短信发送验收取决于AppID/主体/资质。不能用web-view套壳资格作为已知前提。正式上线前核实APP/小程序备案、服务器/域名接入要求、录音隐私声明、第三方数据处理与生成内容标识要求；公开给朋友使用和纯家庭自用的责任边界不同。

## 自动整理与确认

保持原始音频与turn不可覆盖；人物/事件/问题与文学草稿分两阶段，均先draft。每条引用原句、turn_id、近似录音位置、input_hash、模型版本；不能把文字匹配当事实证明。亲属确认后才收入正式书籍。后台失败可重试、幂等、分块和重启恢复，不阻塞实时采访。下一步将后台整理从语音模型的文本模式迁到专门文本模型，以改善结构化输出与成本；需独立文本API凭据与同一数据边界。

# 跨会话章节、素材校订与发布版本

更新：2026-10-24。实时对话保持现有协议。用户已选择本阶段沿用已开通的豆包；下面的独立模型接口不代表已开通其他供应商。

## 使用流程

1. 聊天正常结束或连接中断后，后台自动提取人物、事实、事件与待确认问题，全部是待审核条目；不再为每次新聊天自动拼短故事。
2. 在网页“读与整理 → 跨访谈写章节”勾选多次已结束聊天或导入资料，填写章节标题与写作约定，点击创建生成。
3. 后台依次拟提纲、写正文、事实核对、语言编辑、再次核对。完成后点击“刷新章节与任务”查看草稿及引用。模型核对不替代人工核实。
4. 对照原文、校订快照与原声，保存人工修改，再明确点击“确认此版本收入人生之书”。讲述者的本人入口只显示已确认内容。
5. 新材料或校订后，再选择素材生成新草稿。旧确认版持续可读，只有人工确认新版才切换当前章节；历史确认版仍保留、不可原地编辑。

任务进度目前手动刷新，避免自动刷新覆盖正在编辑的草稿。章节默认继承人物档案权限；本轮未增加章节级私密授权或整本书的 PDF/出版排版功能。

## 模块边界

- `editor_models.py`：extractor / writer 独立私有配置、固定供应商端点、超时/响应限制及脱敏。默认都用 `doubao_realtime`，明确复用现有语音凭据；DeepSeek/Ark 需管理员另行填写真实配置。
- `writing_rules.py`：实际发送给模型的规则和五阶段提示词，版本 `paperlife-biographer-v1`，哈希覆盖固定指令，不包含私人素材。
- `materials.py`：原文与校订选择、不可变任务快照、版本及精确引文检查。
- `editor_jobs.py`：有租约、检查点和最多三次自动尝试的持久化任务，恢复不重复提交产物。失败可人工重试。
- `chapters.py`：章节、草稿编辑计数和人工发布指针，SQLite 事务防止并发确认覆盖。
- `chapter_api.py`：档案授权、模型管理员权限、输入约束。
- `web/life/chapters.js`：跨会话选择、校订、版本对照与私有模型设置；原生小程序本轮保持现有功能，未声称上线或完成章节编辑界面。

## 素材与证据语义

原始聊天引用保留 session、turn、quote 与约秒数。全文人工校订作为独立 revision 引用，`seconds=null, turn_id=null`，仅能回听整段原声，不能声称校订文字与原声逐字对齐。导入文档保留原始 `sources.text`；`material_revisions` 追加校订，原文不被覆盖。

章节快照保存实际采用的文本、版本和哈希。素材后来变化，旧草稿显示过期并拒绝确认，已确认版不自动改变。人工修改章节正文后，旧引文只保留为来源索引，不再声称与新正文逐段对齐；需人工重新核实。

精确引用检查只能证明引文存在，不能证明整段语义或历史事实。独立模型审核提供另一层检查，最终确认仍由本人或获授权编辑完成。本人入口不返回完整生成快照/内部元数据；可通过已确认引文及授权聊天回听核实。编辑台提供完整版本快照。

## HTTP 接口

均在 `/api/life` 下。owner/editor 可编辑，reader 只读确认章节；guest 通过原 `/guest/book` 读取绑定人物的确认章节。

| 接口 | 用途 |
|---|---|
| GET profiles/{p}/materials | 可用于写作的聊天与导入资料，含 revision |
| GET/PUT profiles/{p}/materials/{session或source}/{id} | 原文与校订；PUT 使用 `{text,version}` 乐观锁 |
| GET/POST profiles/{p}/chapters | 列表或创建 `{title,brief}` |
| POST chapters/{id}/generate | `{sources:[{kind,id}],brief?}`，创建独立任务 |
| GET chapters/{id} | 授权范围内的版本；reader 不返回草稿 |
| PUT chapters/{id}/versions/{v} | `{title,body,edit_version}`，只修改草稿 |
| POST chapters/{id}/versions/{v}/confirm | `{edit_version}`，素材变动、发布基线变动或版本冲突返回409 |
| GET profiles/{p}/writing-jobs | 编辑者查看任务进度 |
| POST writing-jobs/{id}/retry | 失败任务重试；不覆盖已完成产物 |
| GET/PUT editor-models | GET脱敏；PUT仅管理员，分别设置extractor/writer |

配置为 `{extractor:{provider,model,api_key?},writer:{...}}`，可只更新一项；同供应商密钥留空保留，换供应商不继承。只允许 doubao_realtime / deepseek / ark 和固定官方端点；密钥只在服务器0600文件，不回显、不写生成元数据。

每章最多选择20份素材，当前章选择总文本上限40000字符，超限明确拒绝，不静默截断。章节输出上限30000字符。实际供应商还有上下文限制；发生超限或无效输出时减少素材/拆章后重试。提取任务按片段处理，不丢长轮尾部。

## 升级与兼容

新增 `material_revisions`, `chapters`, `chapter_versions`, `writing_jobs` 表及 items 的来源快照/生成元数据列；保留旧表、原声文件、原始turn和旧条目。旧 `processing_jobs` 中已排队任务仍可完成，已完成任务不会因升级重跑。新聊天走新的素材提取队列。

校订现有聊天会追加校订版本并排入新整理任务；单纯再次点击整理不会重复相同输入的已存在任务。章节的再次生成会形成新任务/版本；同一个尚未完成请求会去重。当前单进程部署边界不变，不可据此宣称支持多实例横向扩展。

公共仓库无真实个人资料。旧 paperbridge 站只回补同一版本的业务文件、网页及必要测试，保留宿主账号认证，按该仓库的 `promote_to_main.sh` 发布；不让两个实例共写同一个私有资料库。

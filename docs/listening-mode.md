# 旁听外放通话

执行任务：[Issue #5](https://github.com/houxinli/paperlife/issues/5)；长通话（单段2小时、自动续录、屏幕常亮）见 [Issue #21](https://github.com/houxinli/paperlife/issues/21)。这是单麦克风的旁听录音，不是自建异地通话系统。初期网页可用，小程序仅兼容阅读已有旁听来源，未实现原生旁听采集入口。

## 如何使用

典型用法：家人与长辈视频通话或打电话并打开外放，另一台手机/iPad 放在旁边，打开人物档案的“聊天”页，展开“旁听家人的通话”。双方知情同意后勾选确认，点击“开始静默旁听”。参与者称呼、关系和谁是档案主体可先填，也可留空；名单不等于声纹，系统不会据此猜谁在说话。

页面只采集混合声音，不播放AI语音。旁听收音关闭浏览器的回声消除、降噪和自动增益（这台设备不放声音，这些处理只会压低外放里另一端的声音）；关掉后手机原始电平很低（实测说话声约 -58 dBFS，识别漏字），所以服务器在保存原声和送识别之前做自动音量（`listening_gain.py`）：只按说话帧调整，停顿时增益不变，峰值约拉到 -10 dBFS，最多放大50倍，软限幅；不做降噪。保存的原声就是调整后的音量。录音时页面边听边显示识别文字，整场从头到尾滚动保留，自动续录的各段接在后面（每段声音组重新编号）；文字和声音分组都是暂定，后面的话会让前面几句继续修正，结束后以录音档案为准。识别结果每5秒存档一次。结束按钮停止麦克风，连接继续等待ASR二遍最终结果。

长通话：

- 录音期间网页申请屏幕常亮（Screen Wake Lock）。浏览器不支持或系统拒绝时页面提示手动关闭自动锁屏；锁屏、切到后台或音频上下文暂停仍会结束录音，不续录。
- 单段最长2小时。到时长上限、网络中断、服务重启、上传跟不上或识别连接失败时，麦克风不停，页面自动用新票据接着录下一段，标题加“（第N段）”；每段是独立的旁听记录，各自核实声音分组。两段之间有几秒到一两分钟的空档没有录音。
- 上一段还在收尾（409）、网络或服务暂时不可用时在3分钟内重试；连续3段都没能开始识别或撑不到1分钟（网络太差时避免切出一串很短的段）、超过3分钟仍接不上，或遇到未登录/无权限/次数用完等不会自愈的错误时停止，已收到的录音都保留。第一段就连不上时直接报错，不自动重试。
- 2小时录音会持续亮屏和上传，请接上电源，使用稳定 Wi-Fi。

录音档案中打开旁听记录：

1. 回听片段，添加/修改参与者称呼与关系，选择档案主体。
2. 把声音组绑定到对应参与者；多个组绑到同一个人就是合并。未知可保留未知。
3. 单句分错时选另一个声音组；需要拆分可添加手动组。识别错字可逐句校订。
4. 保存会新增归属版本，初始文字和分组保留。至少一个声音组经人工绑定为主体后，资料才进入提取与章节流程；不能把所有人的“我”当作主体。

“读与整理”的跨访谈章节素材列表可选旁听记录。改变人名、主体或单句归属也会使旧草稿过期；已确认章节保留原版本，需重新生成、审核和确认才能更新。

## 录音中的辅助：给声音起名与 AI 笔记

**给声音起名**（家人账号；专属链接的长辈不能修改身份，不显示）：
- 字幕上方按出现顺序列出这一段的声音组。每组一个下拉框，可选名单里的人、档案主体、“我”，也可以现场加新名字。名单为空时，自动补上档案本人（档案主体）和“我”。
- 选完立即用名字显示这一段的字幕，并通过 WS 控制消息发给服务器。
- 这一段结束、识别定稿后，服务器只把最终识别里确实出现的声音组，按标注保存为第一版归属（与人工在录音档案里保存相同，会使素材进入整理）。之后仍可在录音档案里修改，修改追加新版本。
- 标注是家人边听边手动做的，不是系统按名单或声纹自动猜测。临时识别的声音分组可能在定稿时变化，所以事后请在录音档案里快速核对。
- 自动续录的下一段声音组重新编号，需要重新选。

**AI 实时笔记**（开始录音前勾选，默认开启；专属链接不提供）：
- 约每分钟一次，新增识别文字不足 60 字就跳过。
- 把最近约 3000 字的暂定识别（标了名字的显示名字）和已记过的要点交给“素材编辑”角色的文本模型，生成最多 6 条新要点和 3 条可以追问的问题。
- 笔记只显示在录音页面上，供提问的家人参考：不写进档案，也不进素材整理流程。正式整理仍按原有审核流程进行。
- 模型失败只提示一次“这次没有生成”，不影响录音和识别。文本模型未配置时提示并关闭。每次调用都会产生文本模型用量。

WS 控制消息（网页 → 服务器）：
- `{"type":"stop"}`
- `{"type":"notes","enabled":true}`
- `{"type":"labels","participants":[...],"labels":{"声音组":"参与者ID或null"}}`，单条最长 8000 字符。

服务器事件：
- `listening_transcript`：`{from,segments,total,final}`
- `listening_notes`：`{points,questions}` 或 `{error}`
- 结束时的 `saved` 带 `labels_saved`，表示这一段是否按标注保存了归属。

## 来源与权限

`listening_originals` 保存临时累计识别，最终完成/不完整时冻结一次；`listening_annotations` 保存可选名单、声音组绑定与单句文字/归属修订。原声仍是私有WAV。修订增加sessions.version，证据带segment、时间、speaker身份/主体标记、归属版本、原始文字与分组。修改分句文字后回听指向原录音片段，不承诺逐字对齐。

guest只能录绑定档案及只读历史，不能修订身份；普通reader也不可修改，owner/editor可修改。身份绑定不授予账号权限，不建立跨录音永久声纹库。未完成录音不能校订，校订接口乐观锁冲突返回409。

旁听内容不会触发AI偏好学习或语音退出意图，也不会作为下一次普通AI对话的“上次本人聊天”注入。写作提示词要求明确区分主体、他人补充与未知声音。

## 协议与配置

ASR使用独立服务，默认关闭，复用现有私有语音凭据。管理员在页面启用开关前，需在供应商处实际开通对应服务；软件开关不能代替开通。供应商协议、固定端点、20ms采集聚合200ms发包、真实临时分句缺失时间字段的处理见[ASR文档](listening-asr.md)。

| 路径（/api/life 下） | 用途 |
|---|---|
| GET/PUT listening/provider | 脱敏状态/管理员开关 |
| GET guest/listening/provider | 绑定guest查看服务状态 |
| POST profiles/{p}/listening、guest/listening | `{title,participants,consent:true}`，返回一次性票据 |
| WS live | 根据服务端保存的session.mode分发；不信客户端mode |
| GET listening/sessions/{sid}、guest/listening/{sid} | 归属、原始分句、识别完成状态 |
| PUT listening/sessions/{sid} | `{version,participants,bindings,overrides}`，只追加修订 |
| GET listening/sessions/{sid}/versions/{version} | 普通授权成员只读历史归属版本 |

现有完整全文校订入口拒绝旁听记录，避免把结构化身份归属抹掉。原声回听沿用现有授权音频接口，WebSocket不返回任何音频数据。复用原一次性票据、同源检查、权限撤回与活跃会话互斥。

## 验证与边界

离线测试覆盖协议、原声持久化、断线/恢复、原识别冻结、版本冲突、身份未知、分组/单句更正、权限、素材过期及静默界面；录音中辅助覆盖起名后字幕即时改名、按段发送标注、定稿后只保存出现过的声音组为第一版归属、无效或专属链接的标注被忽略，以及实时笔记的名字使用、要点去重、失败不中断、未配置关闭、未勾选不调用、不写入档案；自动音量覆盖安静语音拉到目标、静音与正常音量原样通过、停顿保持增益、突然大声限幅与快速回落；长通话部分覆盖2小时时间界、临时快照节流与最终保存、实时字幕按变化尾部增量拼出全文（含修订与合并）、权限复核频率、收音参数、按段续录（时长上限/断线/409等待/连续失败/致命错误）、常亮申请与释放，以及用户结束或切后台时不续录。真实供应商探针使用28秒双声合成虚构对话：识别两个声音组，收齐终包；完整静默代理验证原WAV字节一致，人工归属后主体/他人区分正确且可进入提取队列。

这不等于四川话、iPad外放回声、低音量另一端和双方抢话的真人验收，也没有验证供应商单连接能否持续2小时（文档未写上限；被提前断开时按续录接上，已识别部分标为不完整）；识别仍可能错字、重复或分错人，需回听校订。识别中断时保留原声和最近快照，并明确标为不完整，不伪装成功。当前不支持冻结后自动重识别整段录音，防止覆盖人工归属；最终结果来自供应商流式二遍链路，不另行调用录音文件识别服务。

# 日常开场与共享核心实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or scoped parallel agents.

**Goal:** 使聊天轻松进入状态，并形成不会双端漂移的音频核心和接口契约。
**Architecture:** 后端统一业务，纯AudioGate单源生成，平台适配独立；不改变鉴权边界。
**Tech Stack:** Python/FastAPI、浏览器JS、微信CommonJS、无依赖生成脚本。
**Spec:** ../specs/2026-10-24-conversation-core-design.md

## Global Constraints

- 不购买资源，不更改实际计费配置；真实语音费用不进公开仓库。
- 不改路由和DB标识符，不覆盖原文，guest保持绑定本人和只读已确认内容。
- 不把开场天气/吃饭回答作为昵称；不虚构天气或位置。

## Review Focus

- Web旧协议兼容与微信严格门控差异不得在提取中丢失。
- 结束/迟到回复/多分句必须在两种构建产物中一致。
- 生成文件要随Docker和微信包交付；禁止手工漂移。
- 打断不能覆盖已经显示过的助手原话。
- 开场不与历史默认topic或命名窗口冲突。

### 任务1：共享音频核心和契约

- [ ] 定义canonical AudioGate API；用原回归+双端共同事件夹具验证。
- [ ] 增加生成脚本和 --check，将产物检查纳入CI与打包。
- [ ] 契约约束真实事件名、音频格式和REST关键形状；修正微信打断后的文字行。
- [ ] 记录代码规模、已共享与仍分开的责任，说明旧站兼容发布边界。

### 任务2：日常开场和产品用语

- [ ] 先写测试证明默认不要求取名/童年，普通回答不触发命名。
- [ ] 修改提示词和中性默认topic；客户端默认不再硬编码童年主题。
- [ ] 更新可见中文用语与文档，保留AI及录音说明。

### 任务3：费用与登记核验

- [ ] 从官方资料/控制台取得可比报价及备案条件。
- [ ] 用户登录后读取语音账单和用量，区分扣款与额度、出账延迟。
- [ ] 根据登记地核实线上办理/代办/实际经营者责任和政府收费。

### 任务4：验证与交付

- [ ] 完整检查、独立审查、重要问题回归修复；同步并发布旧站产品改动。
- [ ] 更新小程序开发包、架构文档及后续清单；如账单登录未完成，明确未核实金额。
